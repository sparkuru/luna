# Deployment and Recovery Contract

## 1. Scope / Trigger

Apply when editing Dockerfiles, Compose, Nginx, server startup/admin commands,
runtime secrets or recovery tooling. The current production boundary is one
`compose.yaml` with Web, API, server SQLite metadata and the pinned internal
MinIO object store. Validate the exact Docker/Compose version on the target;
the deployment must remain usable with the oldest supported Compose binary.

## 2. Signatures

### 启动与停止

以下命令从仓库根目录运行。需要 Docker Engine 与 Compose v2；目标环境若使用
Compose 1.29.x，应使用已验证的 `docker-compose -p <name>` 等价入口。首次启动
不需要预建 PostgreSQL secret、宿主 Node 或初始化脚本；已有根 `.env` 时保留并
核对部署键，不覆盖开发预览或用户配置。

```sh
cp deploy/.env.example .env  # only when .env is absent
docker compose up --build -d
docker compose ps
docker compose exec api node dist/server/server/cli/admin.js create-account
```

最后一条交互式创建账号，密码隐藏输入并确认；没有默认账号或公开注册。打开
`http://127.0.0.1:8080`。跨设备需填写设备可达的服务端 HTTPS 地址，另一台设备的
`localhost` 不是 Compose 宿主。客户端只需要服务端 URL、账号密码和账本解锁密码，
不填写 S3 endpoint、bucket 或 access key；详见[同步使用与边界](ledger-sync-guidelines.md#同步使用与边界)。

`instance-init` creates `data/.luna/minio.env` and the `initialized` marker;
`bucket-init` runs after MinIO starts, creates `luna-sync`, installs a restricted
service access key, and writes `data/.luna/runtime.json` and
`bucket-initialized` as separate atomic files. Both steps reuse valid existing
state. The normal path needs no host Node toolchain, pre-created secret files,
or shell script. Admin account commands require an interactive terminal and
hidden password confirmation.

初始化、权限或未来版本错误会显式失败，API 重试有界。修复原因后重新运行
`docker compose up -d`；半初始化不能当成空安装。日常停止与恢复：

```sh
docker compose stop
docker compose up -d
```

不要用 `docker compose down -v` 日常停止、升级或清理；它可能删除额外配置的持久卷。
正式服务端数据边界是 `./data/`，容器移除不代替备份。

Use an explicit project name (`docker compose -p <name>` or
`docker-compose -p <name>`) instead of relying on a root-level Compose `name:`
field; the latter is rejected by Compose 1.29.x. The root Docker build context
must keep the `docker/` prefix and allowlist entries for `docker/Dockerfile.server`,
`docker/Dockerfile.web`, `deploy/bucket-init.mjs`, `tsconfig.server.json`,
`src/server/**`, and `deploy/server-runtime-package.mjs`, because the classic
builder applies the root `.dockerignore` even when a Dockerfile-specific ignore
file exists. Root production Compose selects `api` and `bucket-init` targets
from the shared server Dockerfile; Web selects `docker/Dockerfile.web`.
Keep Android's BuildKit-only SDK/cache operations in its separate Dockerfile.
Optional Compose files under `docker/` require `--project-directory <repository-root>`;
their context/bind paths remain relative to that root, preserving `.env` and project identity.

### 配置与跨设备 HTTPS

`deploy/.env.example` 只包含非秘密配置。以下是生产 Compose 的键，开发预览的独立
键见[开发环境](../trellis-plus/development.md)。API's internal port is fixed at 3000. The API reads
`data/.luna/runtime.json`; its S3 contents never enter a client response. The
root MinIO credentials are generated by `instance-init` and reused on restart;
separate API credentials are generated by `bucket-init` and reused on restart.
`LUNA_ALLOW_INSECURE_LAN=true` is a deliberate trusted-RFC1918-IPv4
HTTP exception; HTTPS remains required for production or untrusted networks.

| 根 `.env` 键 | 含义 |
| --- | --- |
| `LUNA_BIND_HOST` / `LUNA_PORT` | Web 宿主监听，默认 `127.0.0.1:8080` |
| `LUNA_ALLOWED_ORIGINS` | 逗号分隔的精确 origin，无路径或末尾 `/`；Android 需保留 `https://localhost` |
| `LUNA_ALLOW_INSECURE_LAN` | 默认 `false`，仅显式允许可信 RFC1918 IPv4 HTTP API/开发访问，不允许公网或任意域名 HTTP |
| `LUNA_DATA_PATH` | bind mount，默认 `./data`；只在停机窗口切换到完整校验的恢复目录 |
| `LUNA_UID` / `LUNA_GID` | `data/` 宿主所有者，默认 `1000:1000`，API 以非 root 运行 |

改端口同时修改 origin，例如：

```dotenv
LUNA_PORT=8081
LUNA_ALLOWED_ORIGINS=http://127.0.0.1:8081,http://localhost:8081,https://localhost
```

普通 LAN HTTP 不是完整 Web 离线部署：Service Worker 与 SQLite-WASM/OPFS 需要安全
上下文，普通浏览器会给出 HTTPS/localhost 错误，不静默回退到 IndexedDB 或
localStorage。APK 的内置安全 origin 与旧 WebView 兼容路径见[Android 规范](../frontend/android-runtime.md)。
Compose 不配置 DNS、防火墙或设备证书信任。

`https://luna.majo.im` 是既有跨设备入口；其他安装需替换为自己的受信任域名。外部
TLS 终止层同源代理 `/` 与 `/api/`，同机部署的配置形状如下：

```dotenv
LUNA_BIND_HOST=127.0.0.1
LUNA_PORT=8080
LUNA_ALLOWED_ORIGINS=https://luna.majo.im,https://localhost
LUNA_ALLOW_INSECURE_LAN=false
```

```nginx
server {
    listen 443 ssl;
    server_name luna.majo.im;
    ssl_certificate /path/managed-by-tls-terminator/fullchain.pem;
    ssl_certificate_key /path/managed-by-tls-terminator/private.key;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_set_header Host $host;
        proxy_set_header Origin $http_origin;
        proxy_set_header Authorization $http_authorization;
        proxy_set_header If-Match $http_if_match;
        proxy_set_header If-None-Match $http_if_none_match;
        proxy_set_header Idempotency-Key $http_idempotency_key;
        proxy_set_header X-Forwarded-Proto https;
        proxy_pass_header ETag;
    }

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header Origin $http_origin;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

此路由模板仍须保留 Web 的 COOP `same-origin`、COEP `require-corp`、严格 CSP，以及
API 的 `Cache-Control: no-store, no-transform`、错误状态码、条件写语义和附件协议
头。未知 API 或缺失资源不得改写成应用 shell；强 ETag 要求见[HTTP 规范](http-api-guidelines.md#scenario-strong-etags-through-a-public-tls-edge)。
若代理在另一主机，把 Web bind/upstream 改成仅供代理访问的私有接口或专用隧道，
并用既有防火墙限制到该代理；不公开 API/MinIO 或绑定公网接口。修改路由先独立
配置检查再 reload，保留可回滚版本并核验健康、`/api/v1/meta`、登录与条件写。

DNS、代理到 upstream 的连通性、证书 SAN 与有效期需在目标网络核验。浏览器和
Android 使用系统信任链；私钥只在 TLS 终止层，不进入仓库、镜像或 APK。正式验收
不使用 `ignoreHTTPSErrors`、测试 CA 或证书绕过。

### 备份与恢复操作

`data/` 自动建立，包含 `server.sqlite`、可能存在的 `-wal`/`-shm`、`minio/`，以及
`.luna/{initialized,bucket-initialized,runtime.json,minio.env}`。目录为 0700、安装标记
与秘密为 0600；后两项是内部受限 API/root 凭据，不进入客户端、前端环境变量、
公开 issue 或日志。完整目录必须按敏感数据保存在脱机或异地位置。

与[设备本地备份](../frontend/web-host-and-validation.md#本地账本选择与备份)分别保留；
服务端备份不包含手动模式尚未上传的记录。不能只复制 SQLite，也不能在写入期间
直接复制 WAL 或对象目录。当前产品入口在数据宿主上需要 Node、GNU `cp` 和同机
本地 Unix socket Docker CLI，并以能读取源、保留数值所有权的权限运行：

```sh
docker compose stop
umask 077
mkdir -p backups
node deploy/backup.mjs data backups/luna-data-YYYY-MM-DD
docker compose up -d
docker compose ps
```

备份父目录必须存在，目标必须是新的、与源不重叠的路径；自定义 `LUNA_DATA_PATH`
时传入实际数据路径。备份命令成功前不重启任何写入者。该入口核验完整安装、权限、
所有权、无符号链接/特殊文件及运行容器挂载；它不能阻止并发重启或宿主写入。原
`rsync -a --numeric-ids` 示例只说明完整停写复制原则，不能替代产品入口的拒绝检查。
单个 `server.sqlite` 的哈希也不能证明整个备份完整；恢复前核对全树内容、所有权与
权限，无改名/截断。无法停机则需要同时覆盖 SQLite WAL/SHM 和 MinIO 的一致性
文件系统快照，普通 `cp -r` 不满足该边界。

先在新目录和独立 Compose project 恢复，保留旧安装。以下源文件清单对应当前三个
生产构建目标（两个 Dockerfile），命令仍从原仓库根执行；备份目录需已完整校验，目标 `luna-recovery`
必须不存在：

```sh
mkdir luna-recovery
mkdir luna-recovery/data
rsync -a --numeric-ids backups/luna-data-YYYY-MM-DD/ luna-recovery/data/
cp compose.yaml .dockerignore \
  package.json package-lock.json tsconfig.json tsconfig.server.json vite.web.config.ts luna-recovery/
mkdir -p luna-recovery/docker luna-recovery/deploy luna-recovery/scripts luna-recovery/src
cp docker/Dockerfile.web docker/Dockerfile.server luna-recovery/docker/
cp deploy/instance-init.mjs deploy/nginx.conf deploy/.env.example deploy/backup.mjs \
  deploy/server-runtime-package.mjs deploy/bucket-init.mjs luna-recovery/deploy/
cp scripts/web-offline-plugin.ts luna-recovery/scripts/
cp -r src/server src/shared src/sync src/api-client src/renderer src/web luna-recovery/src/
cp deploy/.env.example luna-recovery/.env
```

启动前在恢复 `.env` 设置空闲回环端口及对应 origin，例如 `LUNA_PORT=8081` 与上面的
8081 origins，保留与备份一致的 `LUNA_UID`/`LUNA_GID`。目标数据不再被原安装挂载：

```sh
cd luna-recovery
docker compose -p luna-recovery up --build -d
docker compose -p luna-recovery ps
curl -fsS http://127.0.0.1:8081/api/v1/meta
```

也可以在同一项目停写并核验完整恢复目录后，临时修改根 `.env` 的 `LUNA_DATA_PATH`，
验证后恢复原值。不要运行期间切换路径。安装身份、账号哈希/会话、SQLite schema、
bucket 与密文对象必须一起恢复；核验 `instanceId` 与原安装一致，然后检查：

1. 原账号登录与账本密码解锁，或新设备选择恢复服务器副本。
2. 工作区、交易、预算历史、墓碑、附件与冲突 inbox 完整。
3. 第二台测试设备完成拉取/合并/条件上传。
4. 日志仅含请求元数据，不含密码、Authorization 或密文正文。

恢复不能找回从未同步的设备记录。客户端先重新读取远端再合并，不盲目覆盖对象；
若备份早于密码重置/会话撤销，恢复后立即重置密码并撤销不再信任的会话。

### 管理与升级

```sh
docker compose exec api node dist/server/server/cli/admin.js reset-password
docker compose exec api node dist/server/server/cli/admin.js cleanup
```

密码重置撤销账号会话，保留设备账本，不能恢复遗忘的账本密码。`cleanup` 清理过期
会话、幂等记录、30 日前安全事件及附件孤儿世代；按需由宿主 cron/外部调度器执行。
升级前备份 `data/`、记录镜像 digest，再在维护窗口执行：

```sh
docker compose stop web api
docker compose build
docker compose up -d
docker compose ps
```

旧 API 必须在 `bucket-init` 更换 root runtime 前停写，新 API healthy 后恢复流量。
迁移失败保留原目录，检查 `api`、`instance-init`、`bucket-init` 状态，先恢复备份到新
project 验证。不要手改 SQLite、删除 `.luna/initialized` 或 MinIO 对象“重置”安装。

## 3. Contracts

- Only Web publishes a host port, loopback by default. API and MinIO remain on
  Compose's private network; public or cross-device use requires a trusted
  HTTPS reverse proxy and a reachable hostname/IP.
- A deployment serving both public Web and the embedded Android client must
  preserve both exact origins in `LUNA_ALLOWED_ORIGINS`, for example
  `https://luna.majo.im,https://localhost`. The latter is the native bundled
  origin, not permission for arbitrary websites or insecure public HTTP.
  Verify its real preflight/login path and reject an unrelated origin.
- Long-lived HTTPS acceptance requires a valid system-trusted certificate,
  installed-key protection and an enabled persistent renewal job whose actual
  execution and validator-before-reload integration are verified. A successful
  not-yet-due renewal check proves the execution path only; do not report it
  as a completed future certificate renewal. Keep a Luna-specific certificate
  and route rollback when the host serves unrelated sites.
- `data/` contains `.luna/runtime.json`, `.luna/minio.env`, the initialization
  marker, `server.sqlite` and its WAL/SHM sidecars, and the MinIO object tree.
  It is the server backup boundary. Do not describe a container layer or a
  single SQLite file as the complete shared ledger backup.
- `deploy/backup.mjs` runs on the data host with Node, GNU `cp` and the
  same-host Docker CLI using a local Unix socket. Reject a non-Unix
  `DOCKER_HOST` even when `DOCKER_CONTEXT` is also set, then require the
  selected context endpoint to be Unix; conflicting remote overrides fail
  before copying. Stop all writers and prevent restart for the entire
  command. It refuses active container mounts overlapping the resolved data
  tree, including parent/nested/read-only mounts, checks again around the
  copy, and publishes an owned staging tree to a new destination. It rejects
  an existing/overlapping destination, incomplete initialization, invalid
  0700 directory/0600 secret permissions or ownership, symbolic links and
  special files. Preserve numeric ownership and the entire boundary, and
  never remove source data or unknown destination contents on failure.
  These checks do not lock Docker restarts or non-container writers and do
  not intercept arbitrary `cp`/`rsync` commands; this remains a controlled
  stopped maintenance window.
- `minio.env` holds only the MinIO root pair (0600); MinIO reads it through
  `MINIO_CONFIG_ENV_FILE`, so Compose and Docker inspect do not contain root
  values. `runtime.json` holds a different access key with `s3:ListBucket` on
  `luna-sync` and `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` only on
  `luna-sync/luna/*`. `bucket-init` checks its policy and key on repeat start.
  An old runtime equal to the root pair is upgraded in place. If creation
  succeeded but writing `runtime.json` was interrupted, the next bootstrap
  removes unreferenced `luna-sync-api` keys with the expected policy before
  issuing a replacement. A missing bucket on an installation with an existing
  runtime fails; it is never silently recreated as empty.
- Bucket initialization's `mc` subprocess targets only the private Compose
  MinIO service. Remove upper/lowercase HTTP, HTTPS and ALL proxy variables
  from that subprocess environment so Docker-injected host proxies cannot
  redirect its internal readiness/policy operations. Keep external build and
  host proxy configuration untouched.
- API's `/data/.luna/minio.env` mount is an empty file and `/data/minio` is an
  unreadable tmpfs. These mounts hide root material and object files despite
  API's writable bind mount for `server.sqlite`. Keep them when changing
  Compose.
- The server SQLite schema stores users, sessions, account-ledger ownership,
  object metadata, idempotency records and sanitized security events. It does
  not store financial plaintext. MinIO stores client-encrypted envelope bytes.
- Server schema v3 also stores exact attachment orphan generations. Expired or
  canceled reservation tokens are fenced before their physical keys enter the
  delayed reconcile queue; `admin cleanup` must run that queue against the
  configured File/S3 object store. Orphan tombstones remain after a successful
  delete so a late upload of the same old generation cannot survive the next
  sweep or affect a newer published key.
- API writes use one in-process writer mutex around authorization, CAS,
  object-store operation and metadata update. The single-instance deployment
  must not be scaled horizontally without a shared locking/transaction design.
- API startup migrates/validates SQLite, waits for MinIO with a bounded retry,
  and only then listens. Health is liveness; readiness also proves schema and
  object-store availability. Failure is visible and never creates an empty
  replacement database.
- The Web image healthcheck probes `127.0.0.1` only after clearing inherited
  HTTP proxy variables; a host-injected proxy must not turn a local Nginx
  healthcheck into a false 502/unhealthy result. MinIO keeps the same runtime
  boundary as the other services: non-root UID/GID, read-only rootfs,
  `cap_drop: ALL`, `no-new-privileges`, a bounded writable `/tmp` tmpfs, and
  the persistent `data/` bind mount.
- The API runtime contains only compiled server code and the runtime roots
  `fastify`, `@fastify/swagger`, `better-sqlite3`, and `@aws-sdk/client-s3`.
  Web/Android clients receive authenticated API access, never S3 credentials.
- Nginx applies `no-store, no-transform` to `/api`, streams requests, preserves Authorization,
  ETag, conditional and idempotency headers, and uses bounded Docker DNS
  re-resolution for API replacement. Unknown API paths and missing assets do
  not receive the application shell.
- Web responses include COOP `same-origin` and COEP `require-corp`, allowing the
  browser client to use the regular multi-tab OPFS VFS. The embedded Android
  client uses SQLite-WASM's `opfs-sahpool` path and does not depend on these
  response headers. Cross-device HTTPS must still preserve them for Web.
- The Web CSP keeps ordinary JavaScript `unsafe-eval` disabled but includes
  `wasm-unsafe-eval`, which is required for the SQLite-WASM module to compile;
  removing it makes every browser ledger open fail as a generic storage error.
- Limits match Fastify: sessions 2 KiB, ledger creation 1 KiB, preferences
  1 MiB and encrypted ledger 12 MiB. Forwarded client IP is not trusted; this
  is a one-instance small-installation rate-limit contract.
- Restore always starts in a new directory/project. Preserve the instance ID,
  account state, object metadata, ETags and exact ciphertext before switching
  traffic. Clients refetch and merge after restore; they never blind-upload an
  old snapshot.

## 4. Validation / Error Matrix

| Condition | Required outcome |
|---|---|
| Empty data directory | `instance-init` creates root file/marker; `bucket-init` creates bucket and limited runtime before API starts |
| Existing initialized data | Root/API credentials and instance identity are reused byte-for-byte; an unexpected access-key policy fails |
| Legacy runtime equals MinIO root | `bucket-init` installs a separate limited key without clearing objects or changing root |
| Existing runtime but MinIO bucket missing | `bucket-init` fails before API starts; do not create an empty replacement bucket |
| Partial `.luna/`, missing runtime after `bucket-initialized`, existing SQLite without runtime, or invalid future schema | Initialization/API fails without clearing data |
| Wrong data ownership/permissions | Container fails visibly; no empty replacement is created |
| MinIO unavailable | API remains unready and retries are bounded |
| Compose v1 parses the project | No root-level `name:` field; use explicit `-p` |
| Classic builder misses server files | Root `.dockerignore` allowlist includes every server build input |
| Web healthcheck returns proxy 502 | Probe loopback with all HTTP proxy variables unset |
| MinIO read-only rootfs cannot start | Provide only bounded `/tmp` tmpfs and persistent `/data` write access |
| SQLite stopped/corrupt | Liveness/readiness and sanitized API errors are distinct |
| Missing JS or unknown API | 404, no application shell |
| API success/error/proxy error | `Cache-Control: no-store, no-transform` |
| Oversized route request | 413 before application state changes |
| Restored object and stale CAS | 412; client re-downloads, merges and retries conditionally |
| Backup while writes are active | Not accepted as a plain file copy; use a stop window or consistent snapshot |
| Product backup sees a running overlapping mount | Nonzero refusal before publication; original data retained |
| Product backup uses a remote Docker daemon, unsafe tree or existing destination | Nonzero refusal; source and unknown destination contents retained |
| Container restart observed during product backup | No accepted backup; owned staging/empty reservation cleaned |
| Docker injects host proxy into bucket initializer | Private MinIO `mc` operations still succeed without global proxy changes |
| Public-only allowed origins replace the embedded origin | Native login is not accepted until exact `https://localhost` is retained and verified |
| Renewal timer is enabled but has not run | Configuration evidence only; execute and inspect the job before claiming the renewal path works |

## 5. Good / Base / Bad Cases

Good: preserve source directory prefixes while staging, run the explicit project
name through the target's actual Compose binary, build with the root allowlist,
then stop API and MinIO, copy the complete `data/` tree with numeric IDs,
restore it into a new Compose project, verify `/api/v1/meta`, login, decryption,
and two-device merge, then switch traffic.

Base: an empty directory runs two ordered, idempotent initializers and an admin
explicitly creates the first account.

Bad: flattening `src/` or `deploy/` during staging, copying only
`server.sqlite`, copying a live WAL/object tree with `cp -r`, deleting
`.luna/initialized` to reset a deployment, exposing MinIO ports, weakening the
MinIO sandbox for a healthcheck, exposing the root file/object mount to API,
or running `down -v` against an existing installation.

## 6. Tests Required

For container configuration moves, run `./hako node --test
tests/deploy/container-layout.test.mjs tests/preview.test.mjs`; check configured
targets, repository build/COPY inputs and the wrapper's actual file/context
arguments. Compare nonsecret `docker compose config` output before/after with
explicit optional-file project-directory, then verify real build contexts and images.

Run `./hako node --test tests/deploy/backup.test.mjs
tests/deploy/instance-init.test.mjs`. Cover full-tree bytes, secret permissions
and numeric ownership, active/parent/nested/read-only mounts, unrelated mounts,
remote daemon selection/conflicting overrides, incomplete state, symlinks,
existing destinations, Docker failure and a restart observed during copy.
Real Compose smoke must invoke the product backup entrypoint both during
runtime (refused) and after stopping writers (accepted), restore its complete
output into a new project and verify the API state below. Do not bypass
inherited host proxies in the passing deployment run.

Run `docker compose config` (and the target's `docker-compose config` when
Compose v1 is in scope), `./hako npm run server:build`, `./hako npm run
web:build`, server tests, and the isolated Compose backup/restore smoke when
Docker images are available. The deployment smoke must assert successful API
and Web image builds under the target builder, healthy Web status despite the
host proxy environment, MinIO's read-only/capability boundary, loopback-only
publishing, stable instance identity, and API-level object readability after
restart. The full smoke must use disposable labeled resources, copy the entire
`data/` boundary, verify stable instance identity and exact ciphertext/ETag,
exercise stale CAS and idempotency, and validate Nginx route and security
headers. It must never touch a user's existing Compose project.
For the two-stage bootstrap, assert root and API keys differ, exact runtime
bytes survive a second start and stopped-copy restore, API cannot read
`minio.env` or list `/data/minio`, the limited key receives 403 for bucket
creation and writes outside `luna/`, and a synthetic old root runtime upgrades
without changing root credentials. Simulate interruption after key creation:
the old key must return 403 after the next bootstrap. Include
`docker/Dockerfile.server`, `docker/Dockerfile.web`, `deploy/bucket-init.mjs`, and `.dockerignore` in
recovery staging so restored `data/` secrets are not sent into the Docker build
context.
For isolated verification without replacing a deployment's local image tags,
`scripts/smoke-server-restore.mjs` accepts `LUNA_RESTORE_API_IMAGE`,
`LUNA_RESTORE_BUCKET_INIT_IMAGE`, `LUNA_RESTORE_INIT_IMAGE` and
`LUNA_RESTORE_MINIO_IMAGE`. Defaults remain the production local API/bucket-init
tags and pinned Node/MinIO images. These selectors do not change production Compose.
Delete the bucket only in a disposable installation and assert a subsequent
bootstrap fails while preserving `runtime.json`.

Human acceptance additionally checks real hostname routing, HTTPS certificate
trust on a second browser and Android device, cold/offline local SQLite reopen,
manual-mode unsynced records, and restoration from an off-host copy. A browser
loopback fixture is not evidence for these boundaries.
For a long-lived origin, use fresh independent browser profiles and a fresh
physical Android package with unmodified system trust. Verify transaction and
normalized attachment bytes, then close/relaunch clients and restart only the
owned service. Separate ordinary reload session survival from cold-process
memory-only session clearing: durable profile binding/data must survive and
normal reauthentication/unlock must restore remote access. Review actual logs
without printing credentials, and record certificate issuance, installed files,
renewal job exit status, next schedule and route/data rollback commands.

## 7. Wrong vs Correct

Wrong: run raw `cp` against active API/MinIO, or select a different host's
Docker daemon when checking local data. Correct: stop every writer, keep the
maintenance window closed and run `node deploy/backup.mjs data
/absolute/new-backup` on the same data/Docker host; the parent exists and the
destination is new. Treat the entire resulting tree as sensitive.

Wrong: require users to create `postgres-password` files, expose MinIO keys in
the device UI, let API use MinIO root or read its root file, or call a health
endpoint “ready” while the object store is not available.

Correct: `docker compose up --build -d` initializes one private `data/` folder;
the API uses only a restricted internal S3 key, clients authenticate to the API, and
readiness is withheld until both SQLite metadata and MinIO are usable.
