# 降低首次使用认知负担的直观记账 UI

## Goal

让第一次打开 Luna 的用户在几秒内理解“这里是我的账单，点击这里就能记一笔”，并让日常记账路径足够直接、可重复，而不是先面对一个需要解释的专业财务工作台。

本任务参考用户长期使用的移动记账软件的可观察交互逻辑，不复制其代码、品牌、图标、插画、文案或像素级视觉设计；最终实现必须是 Luna 自己的 Web / Electron / Android UI。

## Confirmed product intent

- 当前 UI 的问题是首次使用理解成本偏高：用户第一眼看不到主要动作，容易停顿；长期会影响留存。
- 目标优先级是“直观、简单、快速完成一笔”，而不是首屏一次展示所有专业能力。
- 视频参考软件的核心心智模型是：最近账单是首页，记账入口始终明显，收入/支出先分流，分类选择直接，统计作为独立入口。
- 跨端应共享同一个心智模型；桌面端可以利用更大的空间展示更多账单上下文，但不能因此把完整专业工作台重新放回首屏主路径。
- 最新范围修订统一 Web 的桌面端与窄屏模型：主界面先突出账本、信息、最近账单和“记一笔”；不再让右侧常驻完整快速记账面板成为首页的固定视觉块。桌面端可在弹窗、账单详情和二级菜单中承载更多信息。
- 这次要降低 UI 的认知负担，但不降低数据安全、离线可用性、财务冲突显式性或金额隐私边界。

## Scope revision (2026-09-07)

用户最新确认的首页层级覆盖此前“桌面端右侧常驻快速记账面板”的方案，改为同一套跨端心智模型：

- 主界面只保留 Luna logo、账本/月份等信息、显眼的 `page-heading` banner、日期入口、最近账单、收入/支出/结余三项摘要和显眼的“记一笔”入口。
- 最近账单保留类型、分类、关键词等筛选能力，但默认视觉弱化为次级操作；筛选仍必须可点击、可键盘访问，并且不能影响账单条目本身的编辑/删除入口。
- “记一笔”打开一个类似弹框的可访问交易录入窗口；支出/收入、金额、分类是第一层核心字段，分类使用弹窗/选择器完成，高级日期、商户、支付方式、备注等按需展开。
- 用一个三横线菜单按钮引出可访问的二级菜单弹框；菜单打开时以遮罩隔离主界面，支持明确关闭、Escape、焦点进入与焦点还原。设置、账本同步与备份、冲突处理、分类统计以及其他当前位于主路径下方的管理内容都迁入该菜单，不再占用首页首屏空间。
- “剩余预算”从主界面摘要中移除；月度预算编辑与预算冲突处理保留，并放入二级菜单。

## Repository evidence

- 当前首页在 `src/renderer/renderer.ts:191-240` 生成四个汇总卡片、交易筛选器、右侧完整交易表单、预算编辑器、分类统计和设置；独立的 `#ledger-tools-root` 还会在 `src/web/index.html` / `src/renderer/index.html` 中渲染账本同步与备份。
- 当前交易表单要求同时理解类型、金额、日期、分类、商户、支付方式和备注；代码位置为 `src/renderer/renderer.ts:217-228`。
- 当前交易列表按日期和筛选结果展示，编辑/删除动作直接出现在列表项中；代码位置为 `src/renderer/renderer.ts:341-367`。
- 当前金额隐私规则遮罩顶部收入、支出、结余和剩余预算；本次移除剩余预算摘要后，首页只保留收入、支出、结余三个汇总金额的遮罩，预算详情移入二级菜单后继续保持可见；这是父任务和现有自动化验收需要同步调整的边界。
- 当前 Web-first 规范要求用户可见流程先在 Web host 中实现和验证，再接入 Electron / Android 原生能力；见 `.trellis/spec/frontend/web-host-and-validation.md`。

## In scope

- 重新组织首次打开后的首页信息层级，让最近账单和“记一笔”成为第一视觉焦点。
- 设计响应式增强：桌面端与移动端共享“最近账单 + 记一笔弹窗”的主路径；桌面端在账单条目、详情和二级菜单中展示更多信息。
- 设计收入/支出分流和快速记账弹窗，默认只暴露完成一次记录所需的最少字段，更多字段按需展开。
- 让分类选择、金额输入、日期、备注和保存反馈形成连续、可理解的操作路径。
- 保留统计、设置、账本同步/备份和冲突处理入口，但将高级能力从首屏主路径中降级为可发现的二级菜单。
- 在 Web 入口先验证桌面宽度、窄屏和键盘可用性，再复用到 Electron / Android。
- 保留现有共享领域、`LunaLedgerApi`、SQLite/IndexedDB、加密同步、CNY/i18n、汇总隐私、冲突和墓碑语义。

## Out of scope

- 不复制参考软件的品牌名、配色、城市背景、图标资产、插画、文案或源码。
- 不在本任务重新设计账本同步协议、配置加密、数据库 schema 或 Android 原生备份协议。
- 不为了追求“简单”而隐藏错误、取消多分类数据保护、静默覆盖冲突或把交易金额全部遮罩。
- 不在没有明确产品决定前同时实现多套首页信息架构。

## Acceptance criteria

- [ ] 新用户从空状态进入首页后，能通过页面层级和主按钮理解下一步是“记一笔”，无需先阅读同步、预算或存储说明。
- [ ] 日常新增支出和收入都有明确的类型入口；完成一笔记录的主路径不要求先填写不必要的高级字段。
- [ ] 保存成功、保存失败、重复提交、离线状态和空账单状态都有清晰反馈，失败不得伪装成成功。
- [ ] 最近账单仍按日期可读地展示，编辑、删除和多分类交易保护不被简化流程破坏。
- [ ] 顶部汇总隐私只作用于收入、支出、结余三个汇总金额；交易详情和分类统计继续遵守既定可见性边界。
- [ ] 统计、设置、配置同步、账本同步、备份和冲突处理均能从三横线二级菜单找到，但不会与首次记账主路径争夺第一视觉焦点。
- [ ] 桌面宽屏相比移动端提供更多账单上下文，但用户仍能一眼识别最近账单和“记一笔”主入口；不依赖右侧常驻表单。
- [ ] Web Playwright 覆盖空状态、首次记账、收入/支出切换、分类选择、保存反馈、窄屏和键盘路径；Electron/Android 只复用已验证的共享流程。
- [ ] UI 使用独立的 Luna 设计决策和资源，不出现参考软件的品牌或原始素材。

## Key decisions

- 首屏采用“最近账单 + 明确的记一笔入口”，不采用首页直接展开完整专业表单。
- Web 采用“主界面 + 记一笔弹窗 + 三横线按钮二级菜单”的统一模型；桌面端通过弹窗内容、条目详情和菜单内容提供额外信息，不通过常驻右侧表单扩展首屏。
- 复杂字段渐进展开，以降低第一次记账的认知负担；代价是高级字段需要额外一次展开操作。
- 二级菜单使用语义化、可访问的 modal dialog；代价是打开管理内容时主账单暂时被遮罩，但主界面的信息层级更清晰。
- 月度预算编辑与预算冲突处理保留在二级菜单；首页只移除“剩余预算”摘要卡，不删除预算数据能力。

## Deferred / risk

- 参考视频没有展示底层数据模型、同步、冲突和失败语义；这些继续以父任务的领域与跨层规范为准。
- 桌面宽屏可以显示更多辅助信息，但不能让宽屏专属的专业布局成为移动端和首次使用的前置条件。
- Exact spacing, iconography, breakpoint values and visual tokens belong in `design.md` and must use Luna-owned assets.
