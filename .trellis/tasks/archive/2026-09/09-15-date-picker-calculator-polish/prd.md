# 修正日期点击与计算器结果显示

## Goal

让交易日期区域统一使用日历选择，并优化计算器结果的直观显示与视觉层级

## Confirmed Facts

- 交易日期目前由 `src/renderer/features/entry.tsx:651-658` 的原生
  `input[type="date"]` 渲染，保留 `#transaction-date` 和 ISO 日期值
  `YYYY-MM-DD`；Chrome 点击日期片段时会出现蓝色片段选中状态。
- 计算器结果在 `src/renderer/features/entry.tsx:667-674`（Web）和
  `:593-602`（原生）使用 `calculatorResult` 文案包裹；当前文案分别为
  `Exact preview` / `精确预览`。
- `src/shared/amount-expression.ts:160-179` 已经提供面向 UI 的
  `displayAmount`；本轮需要让它按工作区精度展示主体小数位，并在非终止结果末尾附带
  括号中的下一位。工作区精度为 2 时，`10/3` 应显示为 `3.33(3)`，实际保存仍为
  `3.33`。
- 本次是共享 React renderer 的交互和样式调整，不改变交易日期数据格式、计算器求值、
  账本精度或保存金额。

## Requirements

- 日期字段的可见日期区域，无论点击年份、月份、日期还是右侧图标，都进入日历选择
  流程；鼠标点击不再把日期片段作为可编辑文本高亮展示。
- 保留原生日期控件的 `#transaction-date`、`type="date"`、`required`、键盘可达性、
  新建默认今天和编辑保留原日期行为；用户从日历选中的值仍通过现有 `onChange` 写入
  交易草稿。
- 计算器求值后直接展示 `displayAmount`，移除“精确预览 / Exact preview”前缀；主体
  小数位遵循工作区精度，非终止结果继续在末尾使用括号标记，例如精度为 2 时显示
  `3.33(3)`，有限结果显示为 `189.00`。
- 计算器结果保持右上方的显示屏位置，但显示屏需要有足够的尺寸和更醒目的数字排版，
  不能退化成小气的标签；在窄屏下不造成横向溢出或挤压计算器标题、展开控件和按键。
- 日期字段的 hover/focus 反馈与分类选择按钮保持同一套靛蓝边框和浅色背景反馈，
  让两个并列选择控件的交互状态一致。
- 计算器结果应收敛为右上角紧凑的显示屏，只让实际数字占据主要空间，不再渲染横向
  铺开的大片空白结果框；显示屏在桌面和窄屏都不能挤压标题或按键。
- 计算器按键按计算器习惯排列为：`7 8 9 +`、`4 5 6 -`、`1 2 3 ×`、
  `. 0 C ÷`，最后一行放大 `=` 并把退格放在其右侧；`=` 的视觉尺寸应明显高于
  普通按键。
- 计算器按钮不使用扁平白色卡片效果；数字键采用有层次的悬浮圆角按键，hover 时轻微
  上浮、按下时下沉，运算键和清除/退格键有清晰但克制的色彩区分，仍保持 44px 以上的
  可操作尺寸。
- 计算器结果不再作为标题行右侧的小白色标签，而是使用标题下方独立的横向 LCD 风格
  显示区：深色背景、清晰内阴影、数字右对齐且具有足够字号；显示区应与按键区形成
  明确的“显示屏—键盘”层次，并在 375px 下保持完整可见。
- 计算器展开后，鼠标按键和键盘数字/小数点/运算符/退格都只编辑计算器表达式并立即
  显示在 LCD 中；点击 `=` 或按下 `=`、Enter 才求值并把账本精度金额写回金额字段，
  其他交易字段不应被计算器快捷键劫持。
- 交易列表卡片桌面布局中，收支标签和金额需要与右侧编辑、删除等操作共享垂直中心线；
  左侧标题、分类和备注保持两级信息层次。375px 窄屏下收支标签和金额回到主内容顶行，
  仍需可见且不能造成横向溢出。
- 保留 Web、Electron、Android 共用的计算器按键、错误处理、保存金额和无障碍状态文案；
  所有新增可见文案（如需要）必须同时进入 `en` 与 `zh-CN` 目录。

## Key Decisions

- 日期继续以原生 `input[type="date"]` 作为真实表单值和可访问控件，增加覆盖整个字段的
  日历触发交互与自有显示层；优先调用浏览器的 `showPicker()`，不引入第三方日期库。
- 计算器复用 `displayAmount`，让展示主体小数位与工作区精度一致；不重写有理数求值、
  账本舍入或提交金额逻辑。
- 计算器显示屏采用有明确层级的右对齐大数字区域；按键使用四列计算器布局，并让
  `=` 作为底部主操作跨列显示；按键使用统一的圆角悬浮样式，通过阴影和状态位移表达
  可按压性，不依赖额外图像资源。显示屏独立于标题行，使用深色渐变和内阴影模拟
  LCD 层次，但不引入图片资源。
- 计算器维护独立的表达式状态与账本金额草稿；展开状态下在表单范围内只对金额字段和
  计算器控件捕获计算器按键，普通输入区域保留原有行为；求值是唯一的金额回写边界。
- 这两个改动属于同一个交易录入对话框，作为一个轻量前端任务统一交付，不拆分 API 或
  存储子任务。

## Risks / Deferred Items

- 原生日期弹窗由浏览器/宿主提供，Playwright 可以验证触发调用和值流转，但无法对系统
  日历弹窗本身做像素级断言；需要人工核对 Chromium Web 界面和键盘焦点。
- 非 Chromium 宿主若不支持 `showPicker()`，保留原生日期控件的可访问和键盘后备行为；
  本次不实现自定义跨平台日历组件。

## Out of Scope

- 不改变日期的存储格式、时区规则、默认今天规则、编辑语义或账本月份筛选。
- 不改变计算器的运算符、优先级、除零错误、账本精度舍入和提交金额；仅调整展示精度
  和视觉排版。
- 不新增日期库、远程服务、日期范围选择、时间选择或独立计算器页面。
