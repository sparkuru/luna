# Luna 全流程体验评估与修改计划

评估时间：2026-09-22 至 09-23，Asia/Singapore。对象：`paycheck-to-paycheck` 分支、HEAD `d22eff0` 加当前未提交改动，包含设置界面整理。用户授权范围为自动测试、体验评估与修改规划；本轮未修改产品代码，未创建 Trellis 任务。

**结论：日常记账和数据保护的基础比较扎实，但首次恢复入口存在断路，手机摘要金额被按钮覆盖，设置与恢复流程仍明显偏向实现结构。建议先修复入口、可读性和错误反馈，再压缩设置导航与技术说明；保留已有的离线能力和记账主线。**

## 3. 应保留的优势

1. **记账主线集中。** 首页一个突出记账入口，账单在主体区域，筛选默认收起；手机号页面可以直接看到两笔记录。不要为了容纳设置或同步说明挤占这个主线。
2. **基础录入简洁，可选信息后置。** 金额、分类、日期优先，计算器、更多信息按需展开；保留金额自动聚焦、键盘计算和默认今天的行为。
3. **用户能明确知道保存发生在本机。** 实际保存后有可见反馈；离线仍可新增并重开。继续区分“已保存到本机”与“已同步”。
4. **草稿与并发保护扎实。** 关闭录入框后重开仍是 15；刷新前触发浏览器离开确认。用户确认离开后草稿清空符合当前会话语义，不要误判为静默丢失。保留旧版本写入拒绝、错误保留草稿和不重复提交机制。
5. **备份和同步的数据保护有实测支持。** 错密码、拒绝访问、冲突等不会用“成功”掩盖失败；完整备份能恢复，冲突需要显式选择。界面简化不可削弱这些保护。
6. **已有可访问性基础。** 可见 focus、语义按钮、标签、跳到主内容、reduced-motion、嵌套弹窗焦点恢复，以及统计的文字明细替代入口应保留。此结论不等价于全面无障碍认证。
7. **隐私契约明确。** 摘要可逐项临时显示，重载恢复默认；交易和统计详情仍可见是现有产品约定。修复布局时不要擅自扩大或取消隐私范围。
8. **视觉基线可以延续。** 月白背景、靛蓝主色、统一卡片和克制图标适合本地记账；无需整体更换风格、字体库或新增重型依赖。

## 4. 已确认的问题与设计方向

### F01 · P1 · 全新用户无法从可见入口恢复已有账本

**复现**：全新浏览器 → 欢迎页 → 右上菜单按钮 → URL 到 `/settings`，主体仍是建账表单；备份卡片 0 个、登录控件 0 个。生产版重复验证相同。只有手动输入 `/settings/backup` 才出现恢复区，而且仍排在完整建账表单之后。欢迎页“可在设置中恢复”的承诺与实际入口不一致。

**影响**：换设备的用户可能误建空账本，随后面对“不同工作区备份被拒绝”的另一层障碍；这条后果是风险推断，不是本轮已观察到的数据损坏。

**证据**：[入口死路截图](probe-setup-settings-dead-end.png)、[直接访问恢复页](probe-empty-restore-reachable.png)、`probes.json` 的 `fresh-user-restore-entry`；代码 `src/renderer/app/shell.tsx` 无 workspace 时的兜底只渲染 Setup，仅给 backup 深链接追加工具面板。

**设计**：欢迎页显式提供“新建账本”“从备份恢复”“连接已有账本”三条路径，创建为主按钮，其余为清楚的次入口。恢复页用恢复表单作为主体，不再先要求建账。未建立本地账本也应能进入账号登录/恢复流程；在数据和账号 API 约束内复用已有恢复能力。

**验收**：两个全新 browser context，第二个只能通过可见 UI 点击开始恢复，不能 `goto('/settings/backup')` 或通过 API 预建工作区；覆盖离线备份恢复、账号恢复、错误密码、取消返回。无额外空账本被创建。

### F02 · P1 · 手机首页金额与隐私眼睛按钮重叠

**复现**：375px 首页，支出摘要为 `••••`；点击眼睛显示 `¥28.50`，眼睛仍覆盖金额末尾。生产实测金额范围 x=286.61～347.81，按钮范围 x=309.41～353.41，纵向也相交。其他两个隐藏摘要也重叠。

**证据**：[隐藏态](prod-mobile-masked.png)、[显示态](prod-mobile-revealed.png)、`layout.json`。这是可读性缺陷，不只是审美偏好。

**设计**：每行固定“标签/辅助信息、金额、44px 隐私按钮”三列，金额与按钮独立占位；长金额用可读的布局降级，不能让图标覆盖数字。

**验收**：320/375/768px、中英文、隐藏/显示、负数、大额和 JPY 零小数场景，金额与图标包围盒不相交；按钮不少于 44×44；隐藏金额仍不泄露到 DOM 或无障碍文本。

### F03 · P1 · 备份/冲突页面复用同步说明，任务语义不匹配

**事实**：未登录也能做本地加密备份，但备份页顶部写“按四步操作：登录 Luna 统一账号……”并显示“同步未连接”。零冲突时冲突页只剩“账本同步与备份”和上述同步说明，没有“当前没有冲突”。设置卡片写“有 0 项冲突待处理”，还把用户指向旧的“账本同步与备份”概念。

**证据**：[备份页](prod-1440-settings-backup.png)、[零冲突页](prod-375-settings-conflicts.png)、[设置首页](1440-settings.png)。来源是 `features/tools.tsx` 的通用页头和 `features/settings-navigation.ts` 的复用 helpKey。

**设计**：同步页叫“账本同步”，备份页叫“备份与恢复”，明确“无需登录，可离线使用”；备份内部清晰区分“导出备份”和“恢复/合并”。冲突页以“当前没有需要处理的冲突”作为正常空态，有冲突时显示数量和选择入口；加载、请求失败不能冒充零冲突。卡片说明专属于各自任务。

**验收**：未登录状态直接完成导出；空账本用“恢复”，已有账本用“合并”并说明后果；0/1/多冲突、加载和失败各有正确页面；旧 URL 保持可达，数据协议和合并安全规则不变。

### F04 · P1 · 表单错误指向错误控件，部分文案无法指导修正

**事实**：金额 28.50、未选分类，点击保存后错误为“请选择与交易类型匹配且已启用的分类”，焦点却回到 `transaction-amount`。欢迎页留空提交只说“请检查输入内容后重试”。选择分类后，旧的分类错误在下一次提交前仍可能留在顶部。备份短密码报错中含 Unicode、UTF-8、字节等实现语言。

**证据**：`probes.json` 的 `category-required-focus`、[欢迎页错误](02-welcome-invalid.png)、[短密码错误](probe-backup-short-password.png)。`features/entry.tsx` 的 catch 无差别聚焦金额框。

**设计**：错误按字段保存，错误在对应输入附近出现；金额有效而分类缺失时聚焦分类按钮；字段改正后清理对应错误。欢迎页明确“请输入账本名称”。密码默认提示“至少 12 个字符”，遇到极端长度再说明上限。保留 alert 宣告、提交防重和输入值。

**验收**：逐一覆盖名称、金额、分类、日期、密码错误；焦点落在实际需要修正的控件，修正后相关错误清除；服务端/网络错误保留表单，不伪装为字段错误。

### F05 · P2 · 手机设置子页导航占据过多首屏空间

**事实**：375px 偏好页标题 y≈462px，语言选择 y≈603px；320px 英文页面首屏几乎全是设置导航，正文在折叠线以下。没有横向溢出，但用户每次进入子页都先扫过三组完整导航。

**证据**：[375px 偏好页](375-settings-preferences.png)、[320px 英文](probe-320-preferences.png)、`layout.json`。

**设计**：手机子页顶部改为“返回设置 + 当前页标题”，其他区域放在“切换设置区域”折叠菜单；设置首页仍保留分组入口。桌面可保留分组导航。偏好页标题用“偏好设置”，避免所有子页都叫“设置”。

**验收**：375×800 进入偏好页时语言和隐私主控件直接可见；320×568 英文至少当前页标题和首个主控件可见；导航折叠不破坏 URL、返回、当前项、键盘和 reduced-motion。

### F06 · P2 · 统计图主交互需要过高点击精度，底栏设置触控偏窄

**事实**：375px 月视图有 30 个可点击柱，单个宽约 4.89px；320px 约 3.81px。页面提示点击柱形查看明细。已有“查看期间明细”展开后提供较大的逐日按钮，因此不是无替代操作，但主图的触摸体验差。375px 中文底栏“设置”按钮实际宽约 30.39px，明显小于项目 44px 控件目标。

**证据**：`layout.json`、[统计主图](prod-375-statistics.png)、[文字明细替代入口](prod-statistics-accessible-alternative.png)。

**设计**：底栏三个入口使用等宽点击区域，至少 44×44。窄屏图表提供按周分段/可滚动的逐日选择，或点图后用宽大的前后日期控制；不通过扩大相互重叠的 hitbox 制造选择歧义。保留清楚可达的文字明细。日均旁注明“截至今日的日均”或相应期间口径。

**验收**：普通触控点击不依赖 4px 目标；每个日期可以通过大控件选择；键盘焦点顺序合理；日/周/月金额及未来日语义不变。不能仅以 DOM click 成功作为触控通过。

### F07 · P2 · 建账和账号页面把技术概念暴露过早

**事实**：建账要求理解“工作区”“小数位数”，预算没有直接标“可选”；手机也说“这台电脑”。账号页把开发环境 HTTP/HTTPS 说明放在首段，同时展示登录表单、四步同步说明、同步模式和副本管理；登录密码没有显示/隐藏控件。

**设计**：面向用户统一使用“账本”，名称给示例、预算标可选；币种默认值保留，小数位数按币种自动设定并移到高级选项。用“这台设备/此浏览器”描述保存位置。账号页未登录时集中呈现地址、账号、密码和可选设备名，技术连接帮助折叠；登录成功后再展示连接账本的下一步。提供密码显隐，保持默认隐藏和既有秘密持久化边界。

**验收**：默认建账只需填写名称即可完成；JPY/其他币种精度仍正确；新设备连接的每一步有明确下一步和返回；不会因简化文案暗示“登录即上传全部本地账本”。

### F08 · P3 · 删除后缺少用户可见的恢复动作

**事实**：删除前有确认，取消后记录保留；确认后显示“交易已从本月统计中删除”。确认文案说保留本地历史，但当前页面没有撤销或历史恢复入口。没有证据证明交易被不可逆物理删除。

**设计**：短期把确认框改为明确显示目标商户/金额/日期的语义弹窗；后续增加“撤销删除”。撤销必须作为新的、受 revision 保护的业务操作设计，不能简单回滚数据库或移除墓碑；如果协议尚不支持，先提供明确的恢复说明，不承诺不存在的功能。

**验收**：取消零写入；删除与撤销都能同步收敛；远端修改/删除竞态不会复活错误版本；键盘焦点返回合理。

### F09 · P3 · 查询与预算的常用路径还可更短

**事实**：手机筛选一次性展开类型、分类、搜索、日期、金额，结果位于长表单下方；存在清除按钮和空结果说明，功能可用。预算页显示当前月份，但没有自身月份切换控件，用户需先到其他页面调整月份再返回。

**设计**：搜索前置，类型/分类作为常用筛选，日期与金额放到“更多条件”；已选条件及结果数量维持可见。预算页复用现有月份选择器，并明确显示正在修改的月份。两者都应保留现有条件和草稿，不因布局重排重置。

**验收**：手机基本文本搜索不必穿过全部高级字段；清除条件一步完成；预算可直接切换月份且未保存修改有保护；历史月份和当前月份互不污染。
