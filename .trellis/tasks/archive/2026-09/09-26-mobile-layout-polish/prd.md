# Luna 移动端布局优化与 22041216UC 实机验证

## Goal

继续优化 Luna Android 手机布局，让首页优先展示账单，常用录入无需穿过两个数字键盘；删减演示式文案，将默认自动同步收敛为后台行为、状态集中在设置；在用户指定的 `192.168.9.11:44643` 验证实际表现。

## Background

- 用户于2026-09-26明确确认继续现有技术栈，并同意包含文案精简和同步收敛的task简报；规划批准，可进入实施。Flutter讨论未改变本任务技术栈。
- 工作区初始干净，分支 `paycheck-to-paycheck`，HEAD `7d5d853`。
- 实机型号 `22041216UC` / xagapro；1080×2460，覆盖 density 378；实际 WebView CSS 视口 `457×999`，DPR 2.3625。
- 手机原无 Luna 包。已安装现有隔离测试 APK `majo.im.luna.lan`，仅创建合成账本“移动布局测试”。现有 APK 是 2026-09-23 构建，不能当作当前源码重建结果。
- 实施期间原端口失效；用户提供 `192.168.9.11:34971`，重新核对同型号后用于最终验收。最终 APK 与真实结果见 `validation.md`。
- 实机首页顶部管理区域高约 148 CSS px，账单标题位于 y≈424。`src/renderer/app/shell.tsx:560` 的 native topbar 包含同步状态、账本选择和设置按钮。
- 录入自动聚焦金额后系统键盘与应用计算器同时出现，视口缩为约709px；分类、日期、保存分别落在 y≈783、904、972。`src/renderer/features/entry.tsx:548` 自动聚焦，`:646` 使用 decimal inputMode，`:674` 在金额 field 内放置常驻计算器。
- 截图 `/tmp/luna-mobile-baseline-setup.png`、`/tmp/luna-mobile-baseline-entry.png` 是实机基线，不是最终产物。
- 用户追加：减少“此设备已可离线使用”等演示式备注；同步默认后台执行，设置对应模块查看状态。
- 已有自动同步依据：`src/shared/settings.ts:142` 默认 automatic；`src/sync/server-host.ts:246` 后的本地写入触发同步，`:1369` 为宿主调度器；`src/web/main.ts:26` 在 online/visibilitychange 时触发。它依赖已连接/解锁的运行中会话，不是关闭应用后的 Android 常驻服务。
- 成功离线提示由 `src/web/main.ts:45` 的生产状态逻辑及 `src/web/index.html` 页脚渲染；修改显示时需保留真实离线资产准备和失败状态的可验证性。现有 `offline-and-storage.spec.ts`、`router-offline.spec.ts` 使用成功文本断言。
- 自动同步回归揭示既有生命周期问题：login/connect 的 transition 会停止远端 probe 而不重启。为满足 ML07，最小修复最后一个 transition 退出时恢复既有调度；不新增 timer 类型、协议或后台服务。加强双端自动上传/周期拉取回归，同时补齐旧 fixture 的 dispose 清理。

## Requirements

- ML01 首页：沿用月白靛蓝、系统字体、Lucide 与四导航加中央记账动作；手机顶部聚焦品牌和当前账本，管理信息通过已有设置入口可达，避免重复同步说明占据主要内容空间。
- ML02 录入：类型、分类、金额、日期先于计算器下方的扩展内容可达；以现有计算器完成常用金额输入，避免金额聚焦时重复显示系统数字键盘。备注等文字字段仍使用系统输入法；硬件输入与表达式求值语义保持可用。
- ML03 布局：收紧手机间距及计算器体积，保留至少48px的主要触控目标；长名称、大金额、320px窄屏与横屏无横向溢出。固定导航和保存动作不能遮住可滚动内容。
- ML04 交互状态：继续保留错误提示、保存中/禁用状态、图片 staging 禁用保存、返回和嵌套分类焦点恢复、关窗保留草稿。业务 DTO、存储及同步协议不变。
- ML05 验证：共享 Web 开发优先，通过真实浏览器的 native presentation 模拟回归，再重建隔离 APK 在指定实机验证中文、英文、类别选择、计算录入、备注键盘、返回、保存及持久化。
- ML06 文案：删减共享主页面中只宣告能力、重复说明或带口号意味的备注；正常就绪时不显示“此设备已可离线使用”及其英文版本。操作所需的字段提示、空状态行动、错误/恢复提示与加密口令等关键说明保持清楚。
- ML07 同步：已配置、连接并解锁的账本默认沿用自动同步，记账时无需先打开设置或按同步按钮；主页面不展示常驻同步状态卡、登录/解锁提醒、同步按钮或成功提示。设置→同步提供当前状态、自动/手动模式、失败原因与重试/解锁入口。保留用户明确选择的手动模式；本地独立账本可直接使用。此处“后台”指应用运行期间的自动调度。

## Acceptance Criteria

- [x] ML01：手机首页顶部比实测基线明显紧凑；三摘要、至少两笔合成记录和中央记账动作可见；账本/同步管理入口仍可达。
- [x] ML02：实机首次打开录入不同时显示两套数字键盘；分类、金额、日期与保存均可通过可见控件和正常滚动访问；无需先滑过完整计算器才能选择分类。
- [x] ML02/04：应用内按键可求值并保存合成金额；备注弹出真实系统键盘，BACK先收起键盘再按现有规则关闭子弹窗/录入；重开草稿保留，已保存记录重启读回。
- [x] ML03：320/375/457px竖屏及短横屏无横溢出；主要控件≥48px；摘要金额与隐私按钮互不遮挡；旧WebView的vh降级仍可滚动到低处控件。窄屏/旧vh来自浏览器，最终457px来自实机。
- [x] ML04/05：中英文、reduced motion、错误/禁用状态有自动化或明确实机证据；桌面Web三列核心表单、可选计算器及单一记账动作回归通过。
- [x] ML05：typecheck、聚焦Playwright、Web构建、APK构建及指定实机检查记录真实结果与截图；不将浏览器模拟表述为Android输入法证明。
- [x] ML06：中文/英文首页与正常启动不再出现常驻离线就绪或类似重复能力宣告；生产Web离线刷新和APK本地启动仍可用，离线资产不可用时仍有真实错误状态。
- [x] ML07：首页/设置归位、两宿主无界面动作自动上传/周期拉取、手动模式保存均通过；新增真实浏览器离线恢复联网及受控可见文档 visibilitychange 场景2/2通过，均停留账单页、设置未挂载且无需同步动作。受控事件不代表Android真实前后台切换，证据边界见 validation.md。
