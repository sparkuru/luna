# 近期漏洞核查与依赖升级评估

## Goal

核查近期漏洞，并按用户后续「帮我更新；然后验证；最后提交」落实已报告的安全补丁，验证产品与构建兼容后完成本地提交。

## Background

- 核查基线：提交 `73b4384`，分支 `paycheck-to-paycheck`，初始工作树干净。

- 原始请求授权建立任务与调查；本次用户在审阅核查结果后，进一步授权更新、由 agent 验证与本地提交。

- 「近期」取 2026-07-24 至 2026-10-22；同时检查当前旧版本尚未修复的较早公告。

## Requirements

- R1：盘点直接及传递 npm 依赖、运行时、容器镜像、Android 构建链的仓库版本，区分生产、客户端和开发用途。
- R2：对照供应商公告、官方版本元数据和 npm audit；记录 CVE/GHSA、受影响范围、修复版本、日期及官方链接。区别版本命中与实际可利用性。
- R3：识别可用补丁、次版本和主要版本更新，优先最小兼容安全修复，列明联动配置和必要回归。
- R4：在 research/ 保存优先级、现有缓解边界、无法验证部分和原始查询证据。
- R5：更新 Capacitor 8.5.3、Node 22.23.4、Electron 44.9.3、Vite 6.4.5、Fastify 5.12.7，以及有修复版本的同主版本传递依赖。保持账本、备份、同步协议与现有安全配置。
- R6：更新 nginx 1.30.6 稳定线及报告中的 JDK/Alpine 构建镜像补丁，联动恢复/测试入口的固定版本；不改变现有服务生命周期和数据目录。
- R7：完成类型、共享/API/契约/同步、Web 浏览器、Electron 打包烟测、APK 构建和相关容器回归；复测 audit 并如实记录无修复项与环境限制，提交明确范围的工作成果。
- R8：修正验证中实际暴露的夹具/工具前置问题，保留原断言：dev 镜像提供 ZIP maker 所需 zip；桌面图片烟测明确启用 sandbox 并等待应用退出后清理；Android 原生日期夹具使用真实表单月份。

## Acceptance Criteria

- AC1：可复核的版本清单与来源，区分声明版本和锁定版本。
- AC2：漏洞与升级目标表有官方依据；明确查询失败、未覆盖和条件性风险。
- AC3：每项优先更新建议有目标版本或可验证选择规则及必要验证，不把 npm audit 等同整个系统安全。
- AC4：依赖/镜像版本按 R5/R6 落地并可重现安装；不修改真实数据、线上服务、个人配置或无关产品行为。
- AC5：R7 的适用检查有实际结果；原生/设备/线上未测部分不标通过；剩余漏洞的路径与修复限制清楚。
- AC6：独立 Trellis check 复核后完成本地提交，保留任务 review，不自动推送、部署或归档。

## Out of Scope

MinIO/数据迁移、Forge 8 与其它主要版本升级、生产环境扫描/访问/部署、漏洞利用、真实账本操作、推送和任务归档。
