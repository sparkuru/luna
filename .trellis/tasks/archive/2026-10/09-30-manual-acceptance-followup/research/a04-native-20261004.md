# A04 retained Android acceptance, 2026-10-04

Result: the revised keyboard / IME / BACK scope passes on physical PLR110,
Android 16, WebView 143.0.7499.34, using an isolated current-source
`majo.im.luna.a04` debug package and synthetic USD ledger. The user cancelled
TalkBack acceptance during this run; it is outside this result. No subjective
satisfaction or audio-quality result is asserted.

## Actual device results

- Amount uses `inputmode=none`. Native Android virtual keyevents evaluate
  `12+3` to `15.00` while the OS IME remains closed. The device has no physical
  alphabetic keyboard: its alphabetic input device is Android's Virtual device.
- Notes open the real Baidu IME (`com.baidu.input_oppo/.ImeService`). Native
  text entry produces the synthetic note. First system BACK hides the IME and
  keeps entry; second closes entry, retains amount/notes and restores the
  Record opener. Reopening recovers the draft.
- Category picker and category-usage BACK close one layer and restore their
  invoking control. Filter BACK returns focus to its filter opener.
- Actual DocumentsUI image selection, backup save and backup import are
  cancelled with native BACK. The entry and committed ledger remain intact;
  no attachment/document is saved. Backup cancellation reports cancellation.
- UI save commits one transaction. Zero amount reports an associated
  `role=alert`, `aria-invalid=true` and `aria-describedby`; short backup
  password reports its validation error. Both errors preserve committed data.
- Force-stop/relaunch recovers the same one transaction, amount `-1500` and
  synthetic note. Real budget IME keeps Save inside the resized viewport;
  first BACK dismisses that IME while retaining the Budget route.
- Android accessibility-tree snapshots show named visible actionable controls
  on Ledger, entry, category picker/detail, Statistics, Budget, Settings,
  Categories and backup choices. Eight-step native virtual TAB samples record
  control order on primary pages and entry/category picker. These are normal
  keyboard/name checks, not spoken-reader traversal.

## Directly discovered correction

The initial actual-device detail BACK test left keyboard focus on BODY after
five seconds. `closeTransactionDetail()` had scheduled focus before Radix
removed its FocusScope. The correction moves opener restoration into the
close-autofocus callback, then queues it after teardown. It preserves the
deleted-opener fallback and does not move focus away from an editor opened
from detail. Markup, labels and visual design are unchanged.

Focused browser regression passes 4/4 across desktop and narrow Chrome:
renderer BACK, visible Close, Escape and editor focus. Typecheck passes;
the full unit suite passes 226/226. A newly built APK was updated over the
same isolated package without clearing its ledger. Native BACK, visible Close,
injected native Escape and Edit now restore/retain the intended focus;
the previously committed transaction remains unchanged.

## Restoration and limits

TalkBack was stopped immediately at user steering. Exact original
`enabled_accessibility_services` and `accessibility_enabled=1` were restored;
only the preexisting GKD service remains enabled/bound and native touch
exploration is false. The task-owned observation APK never bound successfully;
it was uninstalled. No microphone permission or voice implementation was
found in current `src` / AndroidManifest, and none was added.

Both task-owned package IDs, their synthetic app data, three owned native
temporary files and forward 19224 were removed. Save/import/image pickers were
cancelled, so no persistent document fixture exists. The observer and SDK
temporary image tags were removed; normal build cache remains. Global trust
and existing apps were preserved. Local scratch APKs, the observer fixture key
and raw transient files were removed after sanitized evidence capture.

Physical keyboard hardware remains untested; actual IME fulfills the original
keyboard-or-IME path. The tested IME/WebView/device is the exact environment
above. Names/TAB samples do not claim complete assistive-technology traversal
or every vendor's behavior. TalkBack is intentionally excluded by the user's
revised requirement.
