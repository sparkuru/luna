## Replay and evidence contracts

[Replay](a07-clients-20261005.mjs) loads owner-only credentials from
`LUNA_A07_CREDENTIALS`, requiring the current UID and an `a07_*` account name.
`LUNA_A07_DISPOSABLE=1` is required. `LUNA_A07_WORK` selects a task-owned scratch
directory mapped into the Node22/Chrome container; credentials, profiles and
raw snapshots remain outside the repository. The fixed remote origin is
`https://luna.majo.im`. No TLS bypass, browser trust change or route override
is accepted. Failures emit only a fixed stage, because raw Playwright errors
may include secrets. No traces/request headers are captured.

The Chrome modes deliberately use two initially absent profile directories,
one desktop and one 375px context, without sharing storage state. They close
the actual browser processes between modes:

1. `chrome-init`: trusted headers and secure OPFS, UI workspace creation,
   normal UI image selection/normalization, UI login/bind/upload, second fresh
   UI login/recovery, exact normalized image SHA256/length/dimensions, image
   viewer decoding, and normal tab reload/session continuity.
2. Main/VPS session performs the owned service restart and independently
   verifies its instance/data boundary.
3. `chrome-restart`: requires `LUNA_A07_SERVICE_RESTART_VERIFIED=1`; reopen
   both profile directories, assert local workspace/transactions/binding and
   image bytes, log in/unlock again where required, sync through trusted HTTPS,
   and assert remote readback unchanged. A cold browser login requirement is
   expected session-only behavior, not loss of durable account identity.

For a connected physical device, first inventory exact serial/model/package
absence, then install this owned isolated package. Forward only its WebView
debug socket to host loopback 19225 and set
`LUNA_A07_CDP=http://127.0.0.1:19225`:

4. `android-recover`: fresh package UI login/recovery and image viewer/byte
   verification; stage a valid synthetic native PNG and transaction through
   the public host API, then UI sync uploads it. This upload does not prove
   the DocumentsUI selection flow, which has separate A03 evidence.
5. Coordinate another short owned service restart while the native memory
   session remains alive; sync/read back without re-login. Then externally
   force-stop/relaunch only `majo.im.luna.a07`, rebuild the owned
   forward for its new PID, and run `android-restart`; local images/binding
   remain, then UI login/unlock and remote sync/readback succeed.
6. `chrome-after-android` and `chrome-first-after-android`: both original Chrome
   profiles download the Android-originated transaction and verify exactly
   two transactions/two images, including decoded viewers.

Final cleanup closes owned browsers, removes their scratch profiles and
credentials only after evidence is sanitized, removes only the owned ADB
forward/package, and reports any retained APK or data. Persistent deployment
and synthetic-account revocation/cleanup are coordinated by the main session;
the client harness never operates VPS routes or server storage.
