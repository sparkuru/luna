# Web 端视觉重构与响应式体验

## Goal

让 Luna 在浏览器中像一款真正以日常记账为核心的产品：Web 窄窗口先看到当前账单和唯一明确的记账入口，桌面端在不增加认知负担的前提下展示更多信息；页面具有稳定的视觉层级、可读的统计和一致的设置导航。

本任务只处理 Web 浏览器客户端的视觉结构、桌面信息架构、响应式布局、信息层级和交互呈现。后端、账号、账本、同步和权限继续使用同一套逻辑；Web 可以拥有独立于 Android/iOS/mobile 的页面壳和导航模型。移动端专属的导航与交互设计后续另行规划，本任务不以移动端完成为交付条件。

## Confirmed Background

- 用户反馈当前前端“不好看”，明确指出 Web 端尤其达不到预期，并同意为这轮建立 Trellis 任务。
- 已于 2026-09-13 用本地 Vite Web 服务和 Chrome 实际检查 `375×812`、`1440×900`，生成临时证据：`/tmp/luna-ui-review/`。
- 当前 375px 首页实测：`.topbar` 高 171px，主要内容从 y=203 开始；固定底部导航位于 y=725–800，第三条交易行 y=711–782，与底栏发生遮挡。页面无横向溢出，但首屏垂直空间分配不合理。
- 当前 375px 统计页实测总滚动高度约 3178px，趋势卡片约 2019px；月视图逐日渲染 30 个桶，零值和未来日期占据大部分首屏以下空间，分类与大额支出被推远。
- 当前代码证据：顶栏默认允许换行（`src/renderer/styles.css:286-289`），移动端把状态、账本选择、菜单和语言拆成多行（`src/renderer/styles.css:1612-1709`）；移动端首页通过隐藏文案、压缩摘要和固定底栏适配（`src/renderer/styles.css:1711-1780`）；统计页使用趋势/分类双栏且网格项目共享高度（`src/renderer/styles.css:2173-2185`）。
- 现有 renderer 使用 React/TypeScript、Tailwind/shadcn、Lucide 和 CSS 变量；Web 通过共享 renderer 渲染，CSS 必须继续走外部 stylesheet/CSP 约定。
- 项目规范要求 Web-first、桌面与窄窗口双向验证、44–48px 触控目标、键盘和屏幕阅读器可达、保留 loading/empty/error/disabled 状态。已有 `09-12-luna-ui-redesign` 任务中的业务和附件契约是本任务的上游约束；本任务只把其中的 Web surface 作为视觉交付目标。
- UI/UX 检索建议与本产品相符的方向是低动效、扁平/轻量层级、移动优先、每屏一个 primary CTA、固定导航预留安全空间、图表提供文字替代；不采用检索结果中的营销落地页、下载 CTA 或暗色金融仪表盘。

## Requirements

### R1. Web 响应式骨架

- 桌面 Web（优先 `1024px`、`1280px`、`1440px`）是本任务的主设计宽度；`768px` 和横屏窗口提供可用的收缩布局，不能横向溢出或被固定元素遮挡。
- Web 顶栏、账本切换、同步状态和次级入口形成清楚的桌面工作区框架；同步状态仍可发现但不占据账单主层级。
- 一级导航只保留一套清晰的 Web 层级；桌面端使用适合宽屏的信息架构，同一页面不同时展示重复的主导航/记账 CTA。
- 本任务不设计新的移动端底部导航、移动端手势或 Android/iOS 专属交互；窄窗口只保留不阻断基本使用的安全降级。

### R2. 首页账单层级

- 首页首屏优先展示月份、收支摘要、最近交易和一个明确的记账动作；不让同步状态、设置入口或说明文案抢占主层级。
- Web 账单页只保留一个视觉 primary CTA；收入/支出在同一个录入弹层中切换，不再形成三个并列的“添加交易”入口。原生客户端可继续保留各自已有的直接快捷入口。
- 摘要隐私遮罩、单独显示/隐藏、金额格式和交易详情必须保持现有行为；只改变布局和呈现，不把敏感值复制到隐藏 DOM。
- 交易列表在 Web 收缩窗口中保持紧凑但完整可读，操作菜单、详情、编辑、删除和图片入口继续可达。

### R3. 记账入口与弹层

- Web 收缩窗口下记账弹层第一屏必须让用户理解“类型 → 分类 → 金额 → 保存”的路径；分类选择和计算器不能以长页面堆叠到用户失去上下文。
- 复杂字段、备注和附件继续渐进展示；日期、金额、分类和保存动作保持可操作、可聚焦和状态明确。
- 不改变草稿保留、脏状态、原 revision、图片 staging、失败恢复和键盘语义。

### R4. 统计页面

- 周/月/年、收支切换、趋势/分类视图、分类钻取和最大支出能力保持不变；重新设计其布局和信息密度。
- Web 收缩窗口下月趋势不能让 30 个等权日期桶垄断整页；必须通过紧凑可读的趋势表达、分组/折叠或等价信息层级，让分类和大额支出在合理滚动距离内可发现。
- 桌面端趋势与分类卡片按内容高度自然布局，不能因为 CSS grid 等高产生大块无意义空白。
- 图表/趋势交互必须保留可见数值、键盘操作和文字替代；零值、未来日期和空数据状态要有清楚而克制的呈现。

### R5. 设置与次级功能

- 设置首页和子页明确区分偏好、账本、账号、同步、备份和冲突；桌面可展示更多信息，Web 收缩窗口不把所有管理卡片压成密集横排。
- 同步状态、离线能力、桌面专属能力和错误恢复文案必须保持真实，不用视觉重构掩盖不可用状态。
- 既有旧路由和 deep link 继续可达；返回行为、页面焦点和草稿保护不回归。

### R6. 视觉系统与可访问性

- 保留 Luna 当前月白/靛蓝品牌方向和语义收入、支出、危险颜色；通过层级、间距、字体尺度、边界和控件状态提升质感，不引入远程字体、emoji 图标或无必要动效。
- 使用现有 Lucide 图标和语义 CSS 变量；交互目标至少 44px，正文在移动端保持可读字号，焦点环、对比度、ARIA 和键盘顺序不回归。
- 低动效默认，遵守 `prefers-reduced-motion`；不增加会让离线启动变慢的重型图表库或装饰资源。

## Acceptance Criteria

- [ ] 在 `1024px`、`1280px`、`1440×900` 和横屏 Web 窗口下，首页、统计和设置具有清楚的桌面层级，不出现重复导航或大块无意义空白。
- [ ] 在 `768px` Web 窗口下无横向溢出，长标题、大金额、中文/英文切换、菜单和基础账单操作仍可用；不把该窗口当作本任务的移动端最终设计。
- [ ] Web 首页首屏能看到月份、三项摘要、至少两条交易和唯一明确的记账主入口；导航/状态区不遮挡账单内容。
- [ ] Web 录入弹层在桌面与收缩窗口下提供清楚的类型、分类、金额和继续/保存路径；打开分类、计算器、更多字段、附件和关闭/返回均不破坏草稿或焦点。
- [ ] 统计页在周/月/年和空/少量/多量数据下均可发现趋势、分类和最大支出；趋势数据有文本等价内容，键盘可操作，Web 收缩窗口不再由 30 个日期行制造主要视觉负担。
- [ ] 设置首页与各子页在 Web 收缩窗口可导航、在桌面端可读；同步、备份、冲突、账本和偏好入口没有丢失或被伪装成可用。
- [ ] 现有账本行为回归：创建/切换账本、隐私摘要、交易新增/编辑/删除、详情、图片、搜索筛选、预算、旧路由和离线 Web 启动继续通过既有测试。
- [ ] 关键视口截图保存在任务验证目录，并记录实际 viewport、语言、合成数据和未验证边界；不把截图审阅替代真实辅助技术或用户视觉验收。
- [ ] 运行并记录与改动范围相符的 `npm run typecheck`、相关单测、`npm run web:build` 和 `npm run test:web`；失败项需保留原因，不降低验收标准。

## Out of Scope

- 不修改账本 schema、加密/同步/附件协议、服务端 API、数据库迁移或业务金额规则。
- 不新增银行接入、账号自动登录、社区、预测、深色主题、营销落地页或远程字体。
- 不设计或重写 Android/iOS/mobile 的专属导航、底部栏、手势和录入交互；不以重写 Electron/Android 原生壳、真实设备验收或真实部署替代 Web 端设计迭代。共享 renderer 的必要兼容修复除外。
- 不删除现有管理入口、无障碍语义、错误/空态/loading 状态或为了截图而写入用户财务数据。

## Key Decisions

- 视觉重构保持现有月白/靛蓝品牌和安静可信的记账气质，重点投入信息层级、留白、控件重排和响应式密度；不做大幅换肤或营销化表达。用户已确认此方向。
- 后端与账号能力保持统一逻辑，Web 与 Android/iOS/mobile 的页面壳和交互可以不同；本任务先完成桌面 Web，移动端设计与实现后置。用户已确认此边界。
- 桌面 Web（建议 `≥1024px`）使用左侧一级导航；顶部区域用于品牌、当前账本、同步状态和页面上下文，不再承载第二套一级导航。用户已确认此方向。
- 最新 Web 反馈进一步确认：去掉账单页的独立“记一笔支出/收入”按钮；月份使用连贯的胶囊式期间控件，摘要采用轻量信息条，筛选默认收起，设置导航使用齿轮图标。移动端继续只做安全降级，不扩展为本轮设计目标。
- 最新一轮反馈确认：月份加载期间不能闪现旧内容，最近账单必须按所选月份隔离；统计首屏使用紧凑图表/环图并将逐桶明细折叠；预算从 Web 一级导航移入设置工作区分组；语言和本地保存说明移入设置，首页只保留短暂的一条保存/同步反馈；Web 记账按钮放在账单页标题区且只保留一个。

## Technical Notes

- Web 左侧导航与顶部状态区的具体信息密度、折叠方式和页面内次级导航由 `design.md` 确定；实施时不得恢复重复的一级导航。
