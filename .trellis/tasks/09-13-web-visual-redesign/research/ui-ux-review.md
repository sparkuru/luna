# Web 视觉复核与设计依据

日期：2026-09-13

## 实际浏览器证据

使用本地 Vite Web 服务 `http://127.0.0.1:4173` 和 Chrome，建立合成账本与三笔合成交易，分别检查中文 `375×812`、`768` 和 `1440×900` 视口。截图暂存于 `/tmp/luna-ui-review/`，不包含用户真实账单。

### 375px

- 首页 `.topbar` 高 171px，主要内容从 y=203 开始；状态、账本、菜单和语言被拆成多行。
- 固定底部导航位于 y=725–800；第三条交易行位于 y=711–782，底栏覆盖交易列表的可视区域。
- 统计页滚动高度约 3178px，趋势卡约 2019px；月视图的 30 个零值/未来日期桶把分类和大额支出推到很远的位置。
- 录入弹层的分类网格、金额输入和计算器纵向堆叠；在首屏只能看到计算器开头，路径感弱。

### 1440px

- 顶部状态区与一级导航各占一层；“添加交易”、页面内收入/支出按钮重复争夺主操作。
- 统计页趋势与分类使用同高 grid；趋势日期较多时，分类卡右侧留下大块空白。
- 设置页整体可用，但多个管理卡片与顶部二级导航同时出现，视觉上接近后台控制台，缺少当前任务上下文。

## 采用的规则

UI/UX Pro Max 的检索结果与项目规范共同支持以下约束：

- 桌面布局优先使用适合宽屏的导航；不同尺寸使用系统化 breakpoint，不混用多套同层级导航。
- 每个页面只突出一个 primary CTA；次级操作通过层级、颜色和位置降级。
- 固定导航必须为底层内容预留安全空间；交互目标至少 44px；键盘顺序与视觉顺序一致。
- 时间趋势适合折线/紧凑条形表达，分类比较适合降序横条；图表必须保留可见数值和文字替代，不能只靠悬停或颜色。
- 低动效、语义色、Lucide/SVG 图标、移动端不横向溢出和 `prefers-reduced-motion` 保持不变。

## 取舍

检索工具给出的 Newsletter、应用商店下载页、暗色金融仪表盘和远程字体不适合 Luna 的离线记账产品，因此不采用。保留当前月白/靛蓝品牌和现有语义色，把设计资源投入到 Web 桌面侧栏、账单工作区、录入双栏、统计压缩和设置分层。
