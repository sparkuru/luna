# 整理设置界面

## Goal

降低 Luna 设置页的认知负担，让用户能快速判断“我要改什么、当前在哪个区域、操作是否已经生效”，同时保持离线账本、金额隐私、配置同步和跨平台 Web 状态边界不变。

追加主页反馈：主页右侧月份控件已经提供当前月份，因此左侧标题区不再重复展示月份；标题区提示语改为“先看发生了什么，再记下一笔”，并从可扩展的中英文词库中随机选择，让每次进入主页都有轻微变化。

本任务范围是：以 Web 设置体验为主要落地面，整理设置的信息架构、导航、页面层级和视觉呈现；共享 renderer 保持现有设置能力与语义契约，Electron/Android 不进行同范围的外壳视觉重排。

## Background and confirmed facts

- 当前设置路由在 `src/renderer/app/router.tsx` 注册 `/settings`、`/settings/ledgers`、`/settings/categories`、`/settings/preferences`、`/settings/account`、`/settings/sync`、`/settings/sync/advanced`、`/settings/backup` 和 `/settings/conflicts`；`/budget` 是独立路由，但 Web 设置分组把它作为工作区设置入口展示。
- `src/renderer/features/settings.tsx:420-540` 已有设置概览。Web 端将入口分为“工作区”“账号与同步”“数据与恢复”，每个入口使用卡片；概览顶部还显示本地存储状态和同步状态。
- `src/renderer/app/shell.tsx:991-1081` 另有一套设置二级导航。当前 Web 页面可能同时出现分组导航和概览卡片，因此同一层级的入口存在重复呈现。
- `src/renderer/features/settings.tsx:35-417` 将语言、金额隐私、便携设置同步主开关、对象存储连接、测试同步、立即同步和清除连接等不同风险等级的内容放在同一个设置组件中，并通过 `section` 和 `<details>` 分层。
- 已有设置相关能力包括本地账本副本、分类管理、语言、金额隐私、账号/服务端同步、账本同步、加密备份、冲突处理和高级便携设置同步；本任务不应因视觉整理而改变这些能力的业务语义。
- Web 端必须继续通过 `window.lunaLedger` 使用共享 API；Electron 专属的安全秘密持久化在 Web 中应保持明确的不可用/会话态说明，不应伪装为可用能力。
- 现有回归覆盖设置深链接、语言更新竞态、键盘/减少动效、同步配置和备份 disclosure，主要位置为 `tests/e2e/react-state.spec.ts`、`tests/e2e/accessibility.spec.ts`、`tests/e2e/config-sync.spec.ts` 和 `tests/e2e/ledger-tools.spec.ts`。
- 既有 Web 视觉复核记录：设置页“整体可用”，但多个管理卡片与顶部二级导航同时出现时接近后台控制台，缺少当前任务上下文（`.trellis/tasks/09-13-web-visual-redesign/research/ui-ux-review.md`）。
- 项目已确认的 Luna 视觉基线是月白背景、白色 surface、靛蓝主色、语义收入/支出/危险色、系统字体、Lucide 图标、可见 focus、低动效和 375/768/1440 响应式检查；不引入远程字体、emoji 或新的重型 UI 依赖。
- 本次 UUPM 检索建议了 OLED 暗色模式、Lexend/Source Sans 3 和远程字体；这些建议与现有 Luna 轻色产品基线及离线资源约束冲突，因此仅保留其关于可访问性、响应式、渐进披露和状态反馈的通用规则，原始输出记录在 `research/uupm-design-system.md`。

## Requirements

- 设置首页有清楚的页面标题、用途说明和当前状态摘要；入口分组按用户任务组织，而不是按内部实现或协议名称组织。
- 账本主页的月份只由右侧月份控件承担；标题区保留可读的主标题和随机提示语，不重复渲染同一月份。
- 主页提示语必须来自 i18n catalog 和独立词库，每次进入主页随机选择一条；不把用户可见文案硬编码在组件中。
- 同一视图层级只保留一套主要设置导航；概览卡片、侧边/顶部二级导航和返回路径之间有明确的主次关系，不重复争夺注意力。
- 偏好、工作区/账本、账号与同步、数据与恢复、高风险/高级操作之间有可理解的分层；对象存储连接、秘密状态、立即同步、清除连接等高风险操作需要渐进披露和清晰的恢复/确认反馈。
- 保持所有现有设置深链接可达，保留 `/settings/**` 和 `/budget` 的路由语义；如果只做视觉/结构整理，不迁移或删除既有 URL。
- 保持中英文文案完整；所有输入、按钮、导航、状态和错误消息继续使用 i18n catalog，键盘顺序、可见 focus、ARIA 当前项和最小交互尺寸不退化。
- Web 在窄屏和桌面均不产生横向溢出；至少验证 375px、768px、1024px 和 1440px，设置页面不依赖 hover 才能发现关键操作。
- 明确呈现正常、加载、空/未配置、禁用/桌面专属、错误、保存中和保存成功状态；状态色不能是唯一含义，失败时保留恢复路径。
- 不改变设置数据模型、IPC/API、加密、秘密存储、同步协议、账本数据或隐私边界；UI 重排后的已有行为由浏览器回归继续证明。

## Acceptance criteria

- [x] 设置首页和子页的任务分组、当前页指示和返回路径可以被首次使用者理解；同一层级不存在重复且竞争的主要设置入口。
- [x] 现有设置入口（账本、分类、偏好、账号、同步、备份、冲突和高级设置）及 Web 的预算入口仍可从可见导航或概览卡片到达，直接访问原有深链接行为不变。
- [x] 语言、金额隐私、账本/账号同步、加密备份、冲突处理和高级配置的既有功能与安全边界不变；失败不会伪装为成功，也不会清空用户正在编辑的敏感表单。
- [x] Web 在 375px、768px、1024px 和 1440px 下无横向溢出；设置导航保持语义按钮/链接、可见 focus 和项目既有最小尺寸约束，现有键盘/表单回归继续通过。
- [x] 加载、未配置、Web 不可用/桌面专属、错误、保存中、保存成功和危险操作确认状态仍由现有设置 feature 明确呈现并保留恢复动作；本次未改变其状态 owner。
- [x] 中英文 catalog、设置标题/导航/状态/错误和自动化测试定位均保持完整；`prefers-reduced-motion` 不会阻断设置操作。
- [x] 已运行并记录 typecheck、共享单测、Web build、设置/可访问性及完整 Playwright 回归和 `git diff --check`。
- [x] 账本主页不再重复显示左侧月份；提示语改为“再记下一笔”语义，并由中英文词库在每次主页进入时随机选择。

## Out of scope

- 不新增或删除设置能力，不修改设置 schema、`window.lunaLedger`、IPC、SQLite/OPFS/IndexedDB、加密、秘密存储、远端同步或账本数据协议。
- 不在本任务中重做账单、统计、录入、分类业务逻辑；本次追加仅调整账本主页标题区的展示冗余和提示语词库，不改变账单业务行为。
- 不引入远程字体、emoji、重型组件库或新的服务端依赖；不以暗色 OLED 方案替换已确认的 Luna 轻色基线。
- 按本次范围不做 Electron/Android 的独立视觉外壳重排；它们继续消费共享的设置能力和可访问语义。若后续扩大为跨平台外壳同步重排，需要重新扩展范围与验证计划。

## Key decisions

- 本轮采用 Web-first 的信息架构、导航和视觉整理；Electron/Android 外壳不做同范围视觉重排，继续消费共享的设置能力与可访问语义。
- `/settings` 作为设置索引页时由分组卡片承担主要入口；进入 `/settings/**` 子页后保留一套持久的分组二级导航。这样避免 Web 设置首页同时渲染重复的导航和卡片入口，同时保留深层页面的快速切换能力。
- 通过共享的设置区域目录驱动 Web 概览卡片和二级导航，减少路径、分组和文案漂移；路由注册仍由 router 独立负责。
- 保留所有既有 `/settings/**` 和 `/budget` URL，不把视觉整理升级为路由迁移；现有配置表单、同步协议和状态所有权不变。

## Risks and deferred validation

- Web 设置首页不再显示当前的二级导航，已有依赖首页导航按钮的 E2E 需要改为点击概览卡片；这是有意的交互变化，必须同时验证子页导航和浏览器/原生返回路径。
- 共享设置目录会影响 native 的导航生成，但 native 只接受同一份路径/文案元数据，保留现有平铺导航和视觉样式；若出现 native 布局差异，优先隔离 Web 条件渲染/CSS，不修改设置 API。
- Web 端的主观视觉、200% 缩放、辅助技术和真实设备仍需要人工复核；Playwright 只能覆盖语义、键盘、状态和无横向溢出等可自动验证部分。
